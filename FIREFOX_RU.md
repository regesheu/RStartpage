# RStartpage 1.9.0 для Firefox — установка и публикация

Подготовлена отдельная сборка для настольного Firefox 140+. Это неподписанный
архив для временной установки и проверки. Постоянная установка и автоматические
обновления требуют подписи Mozilla. Версия для Android не заявляется.

## 1. Проверить расширение

1. Скачай `RStartpage-Firefox-1.9.0.zip` и распакуй его в отдельную папку.
2. В Firefox открой `about:debugging#/runtime/this-firefox`.
3. Нажми **«Загрузить временное дополнение…»** и выбери `manifest.json` из этой папки.
4. Открой новую вкладку. Если Firefox запросит подтверждение замены новой вкладки,
   разреши его для RStartpage.
5. Открой `about:addons` → **RStartpage → Разрешения**. Для прокси и проверки ссылок
   разреши доступ ко всем сайтам.
6. Проверь новую вкладку, создание и редактирование заметки, сохранение сессии,
   инструменты проверки ссылок и настройки. Исходный интерфейс — английский,
   тема — тёмная. Русский можно выбрать в настройках.
7. Проверь прокси своим рабочим профилем: включение, отключение, исключение сайта,
   Smart Proxy Rule и авторизацию. HTTP, HTTPS, SOCKS4 и SOCKS5 поддержаны;
   логин/пароль — для HTTP, HTTPS и SOCKS5, но не SOCKS4.

После закрытия Firefox временное дополнение удаляется. Перед закрытием или
переустановкой экспортируй данные: на сохранность данных временной установки
рассчитывать нельзя. Переименование ZIP в XPI не заменяет подпись Mozilla.

Иконки сайтов в Firefox пока заменены локальным значком глобуса. Пользовательские
иконки остаются доступны. Адреса закладок не передаются внешнему сервису иконок.

## 2. Перенести данные из Chrome

1. В RStartpage в Chrome открой **Settings → Data** / **Настройки → Данные**.
2. Выбери нужные разделы или все разделы и экспортируй ZIP.
3. Если нужны пароли прокси, включи их отдельным флажком. Архив не зашифрован.
4. В Firefox открой тот же раздел, выбери ZIP и посмотри предварительный состав.
5. Выбери объединение либо замену. Замена перезаписывает выбранные разделы.
6. Проверь результат до включения прокси.

Chrome Sync и Firefox Sync — разные системы. Импорт переносит снимок данных.
Пользовательские названия закладок и текст заметок не переводятся автоматически.

## 3. Использовать Firefox без Google Drive

Google Drive не обязателен. Чтобы использовать встроенную синхронизацию:

1. Открой настройки Firefox → **Синхронизация** и войди в аккаунт Mozilla.
2. Включи синхронизацию **Закладок** и **Дополнений**. Для данных расширения
   важен именно пункт «Дополнения», а не только настройки самого Firefox.
3. На другом настольном Firefox войди в тот же аккаунт и установи RStartpage
   с тем же ID `rstartpage@regesh.ru`.
4. Для нужных небольших заметок включи «Синхронизация» в RStartpage.
5. Полные резервные копии сохраняй через **Настройки → Данные → Экспорт** в ZIP.

Firefox Sync не заменяет облачное хранилище резервных копий. Для данных расширения
доступно 100 КБ суммарно, 8 КБ на одну запись и максимум 512 записей. Закладки
синхронизируются отдельно от этой квоты. Синхронизация данных расширения обычно
происходит раз в 10 минут либо по команде «Синхронизировать сейчас» в Firefox.
Большие заметки, сохранённые сессии и обои можно хранить локально и переносить ZIP.

Источник: https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/storage/sync

## 4. Подключить Google Drive — только если нужен

В архиве без отдельного OAuth client ID Google Drive отключён, с пояснением в
интерфейсе. Существующий Chrome Extension OAuth-клиент для Firefox не подходит.

1. В Google Cloud открой тот же проект, в котором настраивался Chrome. Убедись,
   что включён **Google Drive API** и настроен экран согласия с областью
   `https://www.googleapis.com/auth/drive.appdata`.
2. В Firefox открой `about:debugging#/runtime/this-firefox`, нажми **«Исследовать»**
   рядом с RStartpage и в консоли выполни:
   ```js
   browser.identity.getRedirectURL()
   ```
3. Скопируй полученный HTTPS-адрес полностью, включая завершающий `/`.
4. В Google Cloud открой **Google Auth Platform → Clients → Create client**.
   Тип — **Web application**, название — **RStartpage Firefox**.
5. В **Authorized redirect URIs** добавь адрес из консоли. Если нужен
   **Authorized JavaScript origin**, укажи его origin — без завершающего `/`.
6. Скопируй **Client ID** вида `…apps.googleusercontent.com`.
   Client Secret присылать или помещать в расширение не нужно.
7. В GitHub: репозиторий → **Settings → Secrets and variables → Actions →
   New repository secret**. Имя — `FIREFOX_DRIVE_CLIENT_ID`, значение — Client ID.
8. После отправки/принятия изменений собери настроенную версию и загрузи её в
   Firefox. В локальном терминале можно выполнить:
   ```bash
   FIREFOX_DRIVE_CLIENT_ID='реальный-client-id.apps.googleusercontent.com' bash scripts/build.sh firefox
   ```
9. В расширении: **Settings → Data → Connect Google Drive**. Если OAuth-приложение
   в режиме Testing, твой Google-аккаунт должен входить в список тестовых пользователей.
10. Проверь заметку и резервную копию на двух установках. Доступ к данным приложения
    между Chrome и Firefox нужно подтвердить реальным входом; автоматические тесты
    этого не доказывают.

Токен Firefox хранится только в памяти браузерной сессии и не попадает в архивы.
После истечения срока либо перезапуска может потребоваться повторное подключение.
Реализован клиентский token flow через перехватываемый Firefox redirect; это legacy
OAuth-механизм Google. Переход на рекомендуемый code flow требует отдельного
решения для OAuth-сервиса либо поддерживаемого public client, без встраивания
Client Secret. Подробности и официальные ссылки — в `FIREFOX.md`.

## 5. Опубликовать постоянную версию

1. Зарегистрируйся/войти в https://addons.mozilla.org/developers/.
2. Выбери **Submit a New Add-on → On this site** для публичного каталога и обновлений.
3. Загрузи именно Firefox ZIP и просмотри результаты проверки.
4. Добавь название, описание, скриншоты и адрес поддержки. Политика:
   https://regesheu.github.io/RStartpage/privacy.html — сначала нужно отправить и
   опубликовать подготовленное обновление этой страницы.
5. Постоянный ID дополнения — `rstartpage@regesh.ru`. Не меняй его при обновлениях.
6. Если запросят исходники и сборку, передай исходники соответствующего коммита и
   инструкции из `FIREFOX.md`. Команда сборки — `bash scripts/build.sh firefox`.
7. В пояснениях о данных укажи выбранные пользователем назначения: Firefox Sync,
   Google Drive, прокси и проверяемые сайты. Серверов разработчика и аналитики нет,
   но передача данных при включении этих функций есть.
8. После успешной подписи/проверки установи расширение со страницы Mozilla Add-ons.

Публикация Firefox в Mozilla Add-ons не выполняется автоматически текущим GitHub
release workflow: он лишь собирает архив. Обновления подписанной версии через
каталог Mozilla сохраняют тот же ID и используют увеличенный номер версии.

## Что проверено в этой подготовке

- Общие проверки проекта, архивы, синхронизация заметок, локализация и обе сборки.
- Модульные тесты Firefox: Promise API, схемы прокси, исключения, порядок правил,
  обработка паролей, выключение, разрешения, OAuth state/redirect/scope/expiry.
- Валидатор Mozilla: ошибок нет; предупреждения требуют просмотра перед отправкой.
- Подготовлен тест с настоящим Firefox, локальными HTTP-прокси и открытием страниц.
  Его выполнение в этой среде заблокировано ограничением запуска Firefox;
  GitHub CI также ещё не запускался, потому что отправка ветки требует подтверждения.
- Реальные Google-вход, SOCKS-сервер и подпись Mozilla ещё не проверены.
