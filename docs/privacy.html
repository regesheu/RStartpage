Privacy Policy

RStartpage · Last updated 2026-09-28

Data accessed

RStartpage accesses browser bookmarks to provide its bookmark workspace and uses browser extension storage for notes, saved sessions, preferences and presentation metadata. Session Manager reads tab titles, URLs, order and pinned state when you explicitly save or update a session.

When you explicitly create a note from the toolbar popup, a bookmark, a page or selected page text, RStartpage stores the title, source URL, selected text and other content you choose to save. Link Checker makes user-initiated requests to selected bookmark URLs. Proxy features access browser proxy APIs and authentication events to apply profiles and routing rules you configure.

Data collection and transmission

RStartpage does not operate a developer-controlled backend and does not transmit bookmark data, notes, sessions, settings, proxy profiles, browsing data or credentials to the developer, analytics services, advertising systems or trackers.

Network activity occurs only for features you use. Link Checker connects to destinations you select. Proxy mode routes browser traffic through proxy servers you configure. Chrome/Google may synchronize bookmarks, supported settings, proxy profile definitions and notes you explicitly select when Chrome Sync is enabled.

When you connect Google Drive, RStartpage requests the drive.appdata permission to synchronize notes, groups, tags and deletions automatically, and to create, list, download, restore and delete backups in its own private application-data folder. This permission does not provide access to your other Drive files. While the browser is running, note changes are synchronized and full backups are created daily when data changes. The latest 10 automatic backups are kept; manual and pre-restore backups are not automatically pruned. Automatic and pre-restore backups exclude proxy passwords. Offline edits remain local until connection is restored.

Credentials and archives

Proxy passwords stay local by default. You may explicitly synchronize a password or include passwords in a local archive. You may also explicitly include passwords in a Google Drive backup. RStartpage archives are not encrypted. The connected account identifier/email and a generated device identifier/name are used for account isolation and backup attribution. Google OAuth access tokens are managed by Chrome in the Chrome build. Firefox keeps access tokens only in browser-session memory (storage.session), validates the OAuth redirect, state and scope, and requests reconnection when silent renewal fails. OAuth tokens are never included in backups.

Firefox/Mozilla may synchronize supported settings, proxy profiles and selected notes through Firefox Sync, independently of Chrome Sync. Firefox website icons use a local packaged fallback, with no requests to a third-party favicon service. IPv4 CIDR proxy rules may resolve a hostname through the browser DNS resolver to determine whether it matches a network. Proxy connectivity tests contact fixed connectivity-check endpoints. These requests use the configured routing and may disclose the connecting IP address to those destinations.

Sharing

RStartpage does not sell, rent or share user data for advertising, profiling or unrelated purposes.

Retention and deletion

Bookmarks remain in browser bookmarks until you remove them. Notes, sessions, preferences and metadata remain in browser extension storage until changed, reset or removed. Older automatic backups are pruned after a new backup succeeds, keeping the latest 10. Manual and pre-restore backups remain until deleted. Sync deletion markers prevent old devices from restoring removed notes. A local recovery archive is saved before replacing data. Uninstalling the extension does not intentionally delete your bookmark folder or Google Drive backups.

Limited Use

The use of information received from Chrome APIs adheres to the Chrome Web Store User Data Policy, including the Limited Use requirements.
